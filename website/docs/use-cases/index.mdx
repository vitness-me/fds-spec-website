# What can you do with FDS?

The Fitness Data Standard is a shared vocabulary for fitness data — from a single
exercise up to a twelve-week plan. This section answers one question: **what can you
actually do with it?**

The capabilities build on each other. The **shared library** is the vocabulary
everything else is written in. **Prescription** primitives express intent — how much
load, how many reps, how much rest — as reusable pieces. **Composition** puts those
together into sessions and plans. Read them in that order, or jump to the one that
matches the problem in front of you.

Every example on every page below is loaded straight from a published file in the
standard. Nothing here is illustrative-only, and nothing is hand-typed — if a file is
renamed or a version bumped, the build fails before the page can go stale.

## What FDS deliberately does not do

FDS models no person. There is no athlete identity, no bodyweight, no one-rep max, and
no performed or logged result anywhere in the standard. That is a design decision, not
a gap: a document that describes nobody can be published, cached, mirrored and diffed
freely, with no consent, retention or erasure obligation attached. Every prescription
above references the personal numbers it needs rather than carrying them — see
[Prescription primitives](/docs/use-cases/prescription) for how, and the
[roadmap](/docs/governance/roadmap) for where performed data is deliberately out of
scope.
